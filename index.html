reviewpipe

A pipeline framework for analyzing e-commerce customer reviews — sentiment, recurring themes, and trends — with pluggable input formats, pluggable models, and pluggable output formats.

Point it at raw reviews, get a structured result out. The core has zero ML dependencies; every model- or format-specific piece is its own installable package, so you only pull in what you use.

Get started → GitHub 
import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { LexiconProvider } from '@reviewpipe/provider-lexicon';

const result = await new Pipeline()
  .source(new CsvAdapter())
  .provider(new LexiconProvider()) // no API key, no network, no ML deps
  .run(csvText);

result.overallSentiment; // { score, positive, neutral, negative, reviewCount }
result.trend;            // sentiment per month
result.flagged;          // e.g. 5-star text that reads negative

What it is for

  • Turning a batch of reviews (CSV, JSON, platform exports) into a structured AnalysisResult: overall sentiment, a sentiment trend over time, flagged reviews, recurring themes, and an optional narrative summary.
  • Doing it at the accuracy / cost / privacy tradeoff you choose — from an offline word-list to a frontier LLM — behind one interface.
  • Running fully offline with no API keys (the lexicon and local tiers).

What it is not for

  • Real-time / streaming analysis of individual reviews — it is batch-oriented.
  • A hosted service, database, or dashboard app — it is a library that produces data and static artifacts.
  • Guaranteed state-of-the-art accuracy out of the box — the lexicon tier is a fast baseline; accuracy scales with the tier you pick.

Installation

Requires Node 20+. Install the core plus whichever adapter, provider, and exporter you need:

npm install @reviewpipe/core @reviewpipe/adapter-csv @reviewpipe/provider-lexicon

Pre-release

The packages are not published to a registry yet. Until they are, use reviewpipe from the repository — clone it and run pnpm install, or add a package as a git dependency. The import paths shown throughout these docs are the intended published names.

Each capability is its own package, so a CSV → lexicon → JSON app pulls in exactly one third-party dependency (csv-parse). Heavier tiers keep their model libraries and SDKs as optional peer dependencies.

Quick start

Let's analyze a CSV of reviews end to end.

1. Prepare some reviews

A CSV needs at least a text column. id, rating, date, author, and productId are optional.

id,text,rating,date
1,"Love this jacket, perfect fit and premium material",5,2026-01-04
2,"Shipping took two weeks longer than promised",2,2026-01-06
3,"It's fine, nothing special",3,2026-01-12

2. Run the pipeline

import { readFileSync } from 'node:fs';
import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { LexiconProvider } from '@reviewpipe/provider-lexicon';

const csv = readFileSync('reviews.csv', 'utf8');

const result = await new Pipeline()
  .source(new CsvAdapter())
  .provider(new LexiconProvider())
  .run(csv);

console.log(result.overallSentiment);
// { score: 0.11, positive: 2, neutral: 0, negative: 1, reviewCount: 3 }

3. Write an HTML dashboard

Add an exporter to serialize the result. HtmlExporter produces a self-contained dashboard you can open in a browser.

import { HtmlExporter } from '@reviewpipe/exporter-html';

const html = await new Pipeline()
  .source(new CsvAdapter())
  .provider(new LexiconProvider())
  .export(new HtmlExporter({ title: 'Reviews report' }))
  .run(csv);

writeFileSync('report.html', html);

Tip

With no exporter, run() returns the AnalysisResult object. With an exporter, it returns that exporter's serialized output (a string or Uint8Array).

The pipeline

Pipeline is a small builder that wires four — and an optional fifth — pluggable stages, then runs them:

source(adapter) → use(transformer)* → provider → [themes(extractor)] → [export(exporter)] → run(input)
MethodRequiredWhat it does
.source(adapter)yesSets the input adapter (raw input → reviews).
.use(transformer)noAdds a transform step. Chainable; steps run in the order added.
.provider(provider)yesSets the model provider (sentiment / embeddings / summary).
.themes(extractor)noGroups reviews into labeled themes.
.export(exporter)noSerializes the result. Without one, run() returns the result object.
.run(input)yesExecutes the pipeline. input is passed verbatim to the adapter.

The provider's capabilities flags decide which stages actually run: a provider that can't summarize simply produces no summary, and the pipeline never calls a method a provider doesn't support.

Data model

NormalizedReview

Every adapter produces NormalizedReview[]. Only id, text, and source are guaranteed; real-world exports routinely omit the rest.

FieldTypeNotes
idstringStable id, unique within a run.
textstringReview body; may be empty.
rating?numberStar rating on the source's scale (usually 1–5).
date?stringISO 8601; trend analysis skips reviews without one.
author?stringReviewer name/handle.
productId?stringProduct the review is about.
sourcestringWhere it came from, set by the adapter.
raw?unknownOriginal record, preserved for debugging.

AnalysisResult

The structured output of a run:

FieldTypeNotes
schemaVersionstringThe result schema version (currently 1.0.0).
overallSentimentOverallSentimentMean score in [-1, 1] plus per-label counts.
themesTheme[]Recurring topics; empty unless a theme extractor is set.
summary?stringPresent only when the provider can summarize.
trendTrendPoint[]Average sentiment per month.
flaggedFlaggedReview[]Reviews needing attention (rating/text mismatch, strongly negative).
errorsPipelineError[]Non-fatal per-item failures; empty on a clean run.

Error handling

reviewpipe distinguishes fatal failures from per-item ones.

  • Per-review provider failures are isolated. If classifySentiment throws for one review, that review is recorded in result.errors[] and the run continues — one bad row never crashes the batch.
  • Adapter and transformer failures are fatal. If parsing the input or a transform throws, there is nothing meaningful to analyze, so run() rejects.
  • Summarization failures are non-fatal — recorded in errors[], and the result simply has no summary.
const result = await pipeline.run(csv);
for (const err of result.errors) {
  console.warn(err.stage, err.reviewId, err.message);
  // stage: 'adapter' | 'transform' | 'provider' | 'themes' | 'export'
}

Providers & tiers

All providers implement the same AnalysisProvider interface, so switching tiers is a one-line change. A capabilities flag lets the pipeline degrade gracefully.

TierPackageExtra depsNetworkSent.Embed.Summ.
-1 lexicon@reviewpipe/provider-lexiconnoneno✓——
0 local@reviewpipe/provider-local@xenova/transformersfirst download✓✓—
1 hosted@reviewpipe/provider-huggingfacenone (fetch)yes✓✓✓
2 frontier@reviewpipe/provider-openaiopenaiyes✓✓✓
2 frontier@reviewpipe/provider-anthropic@anthropic-ai/sdkyes✓—✓

Rough guidance: lexicon is fastest and most private (nothing leaves your machine) but least nuanced; local trades a one-time model download for on-device ML; the hosted and frontier tiers add summaries and higher accuracy at the cost of latency, an API key, and sending data to a third party.

Lexicon (Tier -1)

import { LexiconProvider } from '@reviewpipe/provider-lexicon';
new LexiconProvider(); // bundled AFINN word list; scores sentiment offline

Local (Tier 0)

// pnpm add @xenova/transformers
import { LocalProvider } from '@reviewpipe/provider-local';
new LocalProvider(); // distilled sentiment model + embeddings, on-device

Hugging Face (Tier 1)

import { HuggingFaceProvider } from '@reviewpipe/provider-huggingface';
new HuggingFaceProvider({ apiKey: process.env.HF_TOKEN });
// retries 429/503 with backoff; configurable batchSize / batchDelayMs

Frontier (Tier 2)

// pnpm add openai   — or   pnpm add @anthropic-ai/sdk
import { OpenAIProvider } from '@reviewpipe/provider-openai';
import { AnthropicProvider } from '@reviewpipe/provider-anthropic';

new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY });
new AnthropicProvider({ apiKey: process.env.ANTHROPIC_API_KEY });

Both frontier providers set customPrompts: true and accept a promptOverride. Their summarization prompt is exported as SUMMARY_PROMPT so you can inspect or replace it.

Adapters

An adapter turns raw input into NormalizedReview[]. Adapters own input validation.

CsvAdapter

Parses CSV with a header row. The text column is required — a clear error names any missing required column. Remap column names, and set a default source:

import { CsvAdapter } from '@reviewpipe/adapter-csv';

new CsvAdapter({
  columns: { text: 'review_body', rating: 'stars' },
  source: 'amazon-export',
});

FieldMapAdapter (JSON)

Maps NormalizedReview fields to arbitrary JSON dot-paths (a numeric segment indexes an array). Accepts a parsed value or a JSON string.

import { FieldMapAdapter } from '@reviewpipe/adapter-json';

new FieldMapAdapter(
  { text: 'review_body', rating: 'stars', productId: 'product.id' },
  { recordsPath: 'data.reviews' },
);

Transformers

A transformer rewrites the review set before analysis — cleaning, filtering, or deduping. Steps run in the order added. The interface is one method; implementations are yours to write.

import type { Transformer } from '@reviewpipe/core';

const dropEmpty: Transformer = {
  transform: (reviews) => reviews.filter((r) => r.text.trim() !== ''),
};

new Pipeline().source(adapter).use(dropEmpty).provider(provider);

Theme clustering

ClusteringThemeExtractor groups reviews into labeled themes and fills result.themes. When the provider supplies embeddings it clusters with k-means; otherwise it falls back to keyword-frequency grouping — so it works with any provider.

// pnpm add @reviewpipe/clustering
import { ClusteringThemeExtractor } from '@reviewpipe/clustering';

const result = await new Pipeline()
  .source(new CsvAdapter())
  .provider(new LocalProvider())          // embeddings → k-means
  .themes(new ClusteringThemeExtractor())  // or lexicon → keyword fallback
  .run(csv);

result.themes; // [{ label, keywords, mentions, sentiment, exampleReviewIds }]

Each theme carries its distinctive keywords, a mention count, the mean sentiment of its reviews, and a few example review ids. k (cluster count) and the keyword/label counts are configurable.

Exporters

An exporter turns an AnalysisResult into serialized output.

ExporterPackageOutput
JsonExporter@reviewpipe/exporter-jsonPretty JSON; lossless, round-trips exactly.
CsvExporter@reviewpipe/exporter-csvFlat table of themes + trend (a section-tagged tidy schema).
HtmlExporter@reviewpipe/exporter-htmlSelf-contained dashboard, inline SVG charts, no scripts or CDN.
 
import { JsonExporter } from '@reviewpipe/exporter-json';
import { HtmlExporter } from '@reviewpipe/exporter-html';

new JsonExporter({ indent: 2 }).export(result); // string
new HtmlExporter({ title: 'Q1 reviews' }).export(result);

Interfaces

The five pluggable contracts, all exported from @reviewpipe/core. An Awaitable<T> may be returned synchronously or as a promise.

interface SourceAdapter {
  parse(input: unknown): Awaitable<NormalizedReview[]>;
}

interface Transformer {
  transform(reviews: NormalizedReview[]): Awaitable<NormalizedReview[]>;
}

interface AnalysisProvider {
  readonly name: string;
  readonly capabilities: ProviderCapabilities; // gates the optional methods
  classifySentiment?(review: NormalizedReview): Awaitable<SentimentResult>;
  embed?(review: NormalizedReview): Awaitable<number[]>;
  summarize?(reviews: NormalizedReview[]): Awaitable<string>;
}

interface ThemeExtractor {
  extract(items: ThemeItem[]): Awaitable<Theme[]>;
}

interface Exporter {
  export(result: AnalysisResult): Awaitable<string | Uint8Array>;
}

Note

A provider's optional methods are present exactly when the matching capabilities flag is true — sentiment, embeddings, summarization, and customPrompts. The pipeline checks the flag before calling.

Examples

Two runnable reference integrations live in the repository — both offline, no API key:

  • node-batch-script — reads a CSV, runs the pipeline, writes report.json and report.html to disk.
  • express-api — a minimal Express POST /analyze route that accepts a CSV body and returns JSON. 
pnpm install
pnpm --filter node-batch-script start   # writes out/report.{json,html}
pnpm --filter express-api start         # http://localhost:3000

FAQ

Does the core pull in any ML dependencies?

No. @reviewpipe/core has zero runtime dependencies. Model libraries and SDKs live in their own provider packages as optional peer dependencies.

Can I run it with no API key?

Yes — the lexicon tier is fully offline and dependency-free, and the local tier runs on-device after a one-time model download. Only the hosted and frontier tiers need a key.

What's out of scope for V1?

  • Non-English sentiment beyond what a given model supports (the lexicon is English-only).
  • Built-in deduplication or PII-redaction transformers (the interface is provided; implementations are not).
  • Incremental / streaming analysis, persistence, and multi-run diffing.
  • Native embeddings for the Anthropic tier — use the OpenAI or local tier for embedding-based clustering.
