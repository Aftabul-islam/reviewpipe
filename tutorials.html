Tutorials

Learn reviewpipe by building

Each tutorial is a short, runnable walkthrough. Start with the lexicon tier (no API key, no downloads), then move up a tier whenever you want more accuracy, embeddings, or summaries — the code barely changes.

Every tutorial follows the same shape: install → write a few lines → run → read the result. The one line that changes between tiers is .provider(...).

New to the concepts (the Pipeline, NormalizedReview, AnalysisResult)? Skim the documentation first — these tutorials assume you've seen them.

Prerequisites

Node 20+ and a package manager. Examples use TypeScript run with npx tsx file.ts; plain JavaScript works too (node file.js) — reviewpipe ships as ESM.

Pre-release

Until the packages are on npm, install reviewpipe from the repository (clone + pnpm install). The import paths below are the intended published names.

Choose a tier

All tiers implement the same interface, so you can start low and upgrade with a one-line change. Pick by your constraints:

Lexicon · Tier -1

Offline, no key, instant. A fast sentiment baseline (~70% on real data).

Local · Tier 0

On-device ML model. Adds embeddings (for clustering). No key; one-time model download.

Hugging Face · Tier 1

Hosted models over your HF token. Adds summaries.

OpenAI · Tier 2

Frontier quality. Sentiment, embeddings, and summaries. BYO key.

Anthropic · Tier 2

Frontier quality with Claude. Sentiment and summaries (no embeddings). BYO key.

Rule of thumb

Prototype on lexicon (free, offline). Need embeddings/clustering without a key? Use local. Want summaries and higher accuracy? Move to a hosted or frontier tier. The paid tiers call the API once per review — great for modest batches, not tens of thousands of rows.

Lexicon · Tier -1 (offline, no key)

What you'll build: overall sentiment, a monthly trend, and flagged reviews from a CSV — fully offline.

  1. Install 
    npm install @reviewpipe/core @reviewpipe/adapter-csv @reviewpipe/provider-lexicon
  2. Create reviews.csv (only text is required) 
    id,text,rating,date
1,"Love this jacket, perfect fit and premium material",5,2026-01-04
2,"Shipping took two weeks longer than promised",2,2026-01-06
3,"It's fine, nothing special",3,2026-01-12
  3. Write analyze.ts 
    import { readFileSync } from 'node:fs';
import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { LexiconProvider } from '@reviewpipe/provider-lexicon';

const result = await new Pipeline()
  .source(new CsvAdapter())
  .provider(new LexiconProvider())
  .run(readFileSync('reviews.csv', 'utf8'));

console.log(result.overallSentiment);
console.log(result.flagged);
  4. Run it 
    npx tsx analyze.ts
  5. Read the result — overallSentiment has label counts and a mean score in [-1, 1]; trend has average sentiment per month; flagged lists rating/text mismatches and strongly-negative reviews.

Capabilities

sentiment: true · everything else false. No embeddings and no summaries — add a theme extractor for keyword-based themes, or move up a tier.

When to use: prototyping, privacy-sensitive data, or high volume — it processes tens of thousands of reviews per second offline. Accuracy is a modest ~70% on messy real-world text.

Local · Tier 0 (on-device ML, no key)

What you'll build: the same analysis, but with a real sentiment model and embeddings — which unlocks embedding-based theme clustering — all on your machine.

  1. Install (the model library is an optional peer dependency) 
    npm install @reviewpipe/core @reviewpipe/adapter-csv \
  @reviewpipe/provider-local @reviewpipe/clustering @xenova/transformers
  2. Write the pipeline 
    import { readFileSync } from 'node:fs';
import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { LocalProvider } from '@reviewpipe/provider-local';
import { ClusteringThemeExtractor } from '@reviewpipe/clustering';

const result = await new Pipeline()
  .source(new CsvAdapter())
  .provider(new LocalProvider())          // on-device sentiment + embeddings
  .themes(new ClusteringThemeExtractor())  // k-means over the embeddings
  .run(readFileSync('reviews.csv', 'utf8'));

console.log(result.themes); // labeled clusters with mention counts
  3. Run it — npx tsx analyze.ts. The first run downloads the model (cached afterwards; offline from then on).

Capabilities

sentiment: true, embeddings: true. Because embeddings are available, the clusterer uses k-means for higher-quality themes than the keyword fallback.

When to use: you want better sentiment and real theme clustering without sending data to a third party or managing an API key.

Hugging Face · Tier 1 (hosted, bring a token)

What you'll build: hosted sentiment and embeddings, plus a narrative summary of all the reviews.

  1. Install
    npm install @reviewpipe/core @reviewpipe/adapter-csv @reviewpipe/provider-huggingface
  2. Get a token from your Hugging Face account and export it: 
    export HF_TOKEN=hf_...
  3. Write the pipeline 
    import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { HuggingFaceProvider } from '@reviewpipe/provider-huggingface';

const provider = new HuggingFaceProvider({
  apiKey: process.env.HF_TOKEN!,
  batchSize: 20,      // pause after N requests…
  batchDelayMs: 1000, // …to respect free-tier rate limits
});

const result = await new Pipeline().source(new CsvAdapter()).provider(provider).run(csv);
console.log(result.summary);
  4. Run it — npx tsx analyze.ts.

Capabilities

sentiment, embeddings, and summarization all true. It retries 429/503 with exponential backoff automatically.

When to use: you want summaries and hosted models without a heavy SDK, and you're comfortable sending data to Hugging Face.

OpenAI · Tier 2 (frontier, bring a key)

What you'll build: frontier-quality sentiment, embeddings, and summaries — with a custom summary prompt.

  1. Install (the SDK is an optional peer dependency)
    npm install @reviewpipe/core @reviewpipe/adapter-csv @reviewpipe/provider-openai openai
  2. Set your key
    export OPENAI_API_KEY=sk-...
  3. Write the pipeline (with a prompt override) 
    import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { OpenAIProvider } from '@reviewpipe/provider-openai';

const provider = new OpenAIProvider({
  apiKey: process.env.OPENAI_API_KEY!,
  promptOverride: 'Summarize these reviews for a product manager in 3 bullet points.',
});

const result = await new Pipeline().source(new CsvAdapter()).provider(provider).run(csv);
console.log(result.summary);
  4. Run it — npx tsx analyze.ts.

Capabilities

All four true, including customPrompts. The default summary prompt is exported as SUMMARY_PROMPT if you want to inspect or extend it.

When to use: highest accuracy and rich summaries, and you want embeddings from the same provider for clustering.

Anthropic · Tier 2 (Claude, bring a key)

What you'll build: frontier sentiment and summaries with Claude. (Anthropic has no embeddings endpoint — use the OpenAI or local tier if you need embedding-based clustering.)

  1. Install
    npm install @reviewpipe/core @reviewpipe/adapter-csv @reviewpipe/provider-anthropic @anthropic-ai/sdk
  2. Set your key
    export ANTHROPIC_API_KEY=sk-ant-...
  3. Write the pipeline 
    import { Pipeline } from '@reviewpipe/core';
import { CsvAdapter } from '@reviewpipe/adapter-csv';
import { AnthropicProvider } from '@reviewpipe/provider-anthropic';

const provider = new AnthropicProvider({ apiKey: process.env.ANTHROPIC_API_KEY! });

const result = await new Pipeline().source(new CsvAdapter()).provider(provider).run(csv);
console.log(result.overallSentiment, result.summary);
  4. Run it — npx tsx analyze.ts.

Capabilities

sentiment, summarization, and customPrompts true; embeddings: false. Model defaults to a current Claude model; override via the model option.

When to use: you prefer Claude for sentiment and summaries. For clustering, pair it with the local or OpenAI tier's embeddings.

Recipe: CSV & JSON input

Remap CSV columns to the schema:

new CsvAdapter({ columns: { text: 'review_body', rating: 'stars' }, source: 'amazon' });

Map arbitrary JSON via dot-paths (a numeric segment indexes an array), with an optional path to a nested records array:

import { FieldMapAdapter } from '@reviewpipe/adapter-json';

new FieldMapAdapter(
  { text: 'review_body', rating: 'stars', productId: 'product.id' },
  { recordsPath: 'data.reviews' },
);

Recipe: export to JSON / CSV / HTML

Add .export(...) and run() returns serialized output instead of the result object:

import { JsonExporter } from '@reviewpipe/exporter-json';
import { CsvExporter } from '@reviewpipe/exporter-csv';
import { HtmlExporter } from '@reviewpipe/exporter-html';

const html = await pipeline.export(new HtmlExporter({ title: 'Q1 reviews' })).run(csv);
writeFileSync('report.html', html); // self-contained dashboard, opens in a browser

Or keep the result and serialize it directly: new JsonExporter().export(result) / new CsvExporter().export(result).

Recipe: theme clustering

Add a theme extractor to populate result.themes. With an embeddings-capable provider it uses k-means; otherwise it falls back to keyword frequency (rougher, but works with any provider):

import { ClusteringThemeExtractor } from '@reviewpipe/clustering';

await new Pipeline()
  .source(adapter)
  .provider(new LocalProvider())               // embeddings → better themes
  .themes(new ClusteringThemeExtractor({ k: 6 }))
  .run(csv);

Tip

Keyword-fallback themes (when the provider has no embeddings) surface frequent words and can be noisy. Use the local or OpenAI tier for embedding-based themes.

Recipe: a custom transformer

Transformers rewrite the review set before analysis. Implement the one-method interface and chain .use(...):

import type { Transformer } from '@reviewpipe/core';

const dropShort: Transformer = {
  transform: (reviews) => reviews.filter((r) => r.text.trim().length > 10),
};

new Pipeline().source(adapter).use(dropShort).provider(provider);

Recipe: handling errors

Provider failures are isolated per review — a bad row lands in result.errors[] and the run continues. Adapter/transformer failures are fatal (nothing to analyze) and reject.

const result = await pipeline.run(csv);
for (const err of result.errors) {
  console.warn(err.stage, err.reviewId, err.message);
  // stage: 'adapter' | 'transform' | 'provider' | 'themes' | 'export'
}
